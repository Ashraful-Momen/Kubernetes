## **Simple Token Commands for Master Node:**

### **1. Get Current Join Token:**
```bash
# Show existing token (if not expired)
kubeadm token list

# Output shows token and expiration
# TOKEN                     TTL         EXPIRES                ...
# abcdef.1234567890abcdef   23h         2024-01-15T10:30:00Z   ...
```

### **2. Generate NEW Join Token (if expired):**
```bash
# Create new token (default: 24h validity)
kubeadm token create --print-join-command

# Output:
# kubeadm join 10.0.1.10:6443 --token abcdef.1234567890abcdef \
#   --discovery-token-ca-cert-hash sha256:1234abcd...
```

### **3. Generate Token with Custom TTL:**
```bash
# Token valid for 2 hours
kubeadm token create --ttl 2h --print-join-command

# Token valid for 1 week
kubeadm token create --ttl 168h --print-join-command

# Permanent token (careful!)
kubeadm token create --ttl 0 --print-join-command
```

### **4. Save Token to File:**
```bash
# Save join command to file
kubeadm token create --print-join-command > join-worker.sh
chmod +x join-worker.sh

# View saved token
cat join-worker.sh
```

### **5. One-Liner to Get ALL Info for Workers:**
```bash
# Get master IP, token, and hash in one command
echo "MASTER_IP=$(hostname -I | awk '{print $1}')"
echo "JOIN_COMMAND=$(kubeadm token create --print-join-command)"
```

## **Step-by-Step: Convert Worker → Master**

### **Prerequisites:**
1. Worker node already joined to cluster
2. Master has etcd running (check: `kubectl get pods -n kube-system | grep etcd`)
3. Worker has enough resources (2+ CPU, 4+ GB RAM)

### **Step 1: Drain Worker (on existing master):**
```bash
# Drain worker node (move pods to other nodes)
kubectl drain <worker-node-name> --ignore-daemonsets --delete-emptydir-data

# Example:
kubectl drain worker-node1 --ignore-daemonsets --delete-emptydir-data
```

### **Step 2: Generate Certificate Key (on existing master):**
```bash
# Generate certificate key for new control plane
kubeadm init phase upload-certs --upload-certs

# Save the output! Example:
# [upload-certs] Storing the certificates in Secret "kubeadm-certs" in the "kube-system" Namespace
# [upload-certs] Using certificate key: abc123def456ghi789jkl012mno345pqr678stu901
```

### **Step 3: Get Join Command for Control Plane:**
```bash
# Get control plane join command
kubeadm token create --print-join-command --certificate-key <YOUR_CERT_KEY>

# Full example:
kubeadm token create --print-join-command \
  --certificate-key abc123def456ghi789jkl012mno345pqr678stu901

# Output will be LONG, looks like:
# kubeadm join 10.0.1.10:6443 --token xyz789... \
#   --discovery-token-ca-cert-hash sha256:abcd... \
#   --control-plane --certificate-key abc123...
```

### **Step 4: Run on Worker to Become Master:**
```bash
# SSH into worker node
ssh ubuntu@worker-node1

# Run the join command with --control-plane flag
sudo kubeadm join 10.0.1.10:6443 \
  --token xyz789.abcdefghijklmnop \
  --discovery-token-ca-cert-hash sha256:abcd1234... \
  --control-plane \
  --certificate-key abc123def456ghi789jkl012mno345pqr678stu901
```

### **Step 5: Copy Kubeconfig (on new master):**
```bash
# Copy admin config to home directory
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### **Step 6: Uncordon Node (on any master):**
```bash
# Allow scheduling on new master
kubectl uncordon <new-master-node-name>

# Example:
kubectl uncordon worker-node1
```

### **Step 7: Verify New Master:**
```bash
# Check nodes (should show control-plane role)
kubectl get nodes

# Check etcd pods (should have 3 now)
kubectl get pods -n kube-system -l component=etcd

# Check all control plane components
kubectl get pods -n kube-system -l tier=control-plane
```

## **Complete Script: Worker → Master Upgrade**

### **Script to Run on EXISTING Master:**
```bash
#!/bin/bash
# upgrade-worker-to-master.sh

WORKER_NAME="worker-node1"
MASTER_IP="10.0.1.10"

echo "=== Upgrading $WORKER_NAME to Control Plane ==="

echo "1. Draining worker node..."
kubectl drain $WORKER_NAME --ignore-daemonsets --delete-emptydir-data

echo "2. Generating certificate key..."
CERT_KEY=$(kubeadm init phase upload-certs --upload-certs 2>/dev/null | grep "certificate key" | awk '{print $NF}')

echo "3. Creating join token..."
JOIN_CMD=$(kubeadm token create --print-join-command --certificate-key $CERT_KEY 2>/dev/null)
JOIN_CMD="$JOIN_CMD --control-plane --certificate-key $CERT_KEY"

echo "4. Join command for $WORKER_NAME:"
echo "ssh ubuntu@$WORKER_NAME"
echo "sudo $JOIN_CMD"
echo ""
echo "5. After joining, copy kubeconfig:"
echo "mkdir -p \$HOME/.kube"
echo "sudo cp -i /etc/kubernetes/admin.conf \$HOME/.kube/config"
echo "sudo chown \$(id -u):\$(id -g) \$HOME/.kube/config"
echo ""
echo "6. Then uncordon: kubectl uncordon $WORKER_NAME"
```

### **Script to Run on WORKER Node:**
```bash
#!/bin/bash
# become-master.sh

# Paste the join command from previous step
JOIN_COMMAND="kubeadm join 10.0.1.10:6443 --token xyz789.abcdefghijklmnop --discovery-token-ca-cert-hash sha256:abcd1234... --control-plane --certificate-key abc123def456..."

echo "Becoming control plane node..."
sudo $JOIN_COMMAND

echo "Setting up kubeconfig..."
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

echo "Verifying..."
kubectl get nodes
kubectl cluster-info
```

## **Important Notes:**

### **Before Upgrading Worker → Master:**
```bash
# Check if etcd is running as pod (required for HA)
kubectl get pods -n kube-system | grep etcd

# Check worker resources
free -h       # Memory
nproc         # CPU cores
df -h /       # Disk space

# Ensure ports are open on worker (now will need master ports):
# 6443, 2379-2380, 10250, 10259, 10257
```

### **After Upgrade Verification:**
```bash
# All masters should show control-plane role
kubectl get nodes -o wide

# Check etcd cluster health
kubectl exec -n kube-system etcd-$(hostname) -- etcdctl endpoint health

# Check API server endpoints
kubectl get endpoints kube-apiserver -n default

# Test scheduling on new master
kubectl describe node <new-master-name> | grep -A10 -B10 "Taints"
```

### **Troubleshooting:**
```bash
# If join fails: reset and try again
sudo kubeadm reset -f
sudo rm -rf /etc/kubernetes/ /var/lib/etcd

# Check logs on worker/master
sudo journalctl -u kubelet -f
sudo journalctl -xeu kube-apiserver

# Verify certificates
sudo openssl x509 -in /etc/kubernetes/pki/ca.crt -text | grep -A5 "Subject:"

# Check network connectivity between masters
ping <other-master-ip>
nc -zv <other-master-ip> 6443
```

## **Quick Reference Card:**

### **Token Management:**
```bash
# Create token:     kubeadm token create --print-join-command
# List tokens:      kubeadm token list
# Delete token:     kubeadm token delete <token-id>
# Generate cert:    kubeadm init phase upload-certs --upload-certs
```

### **Worker → Master Steps:**
```bash
1. kubectl drain <worker>
2. kubeadm init phase upload-certs --upload-certs
3. kubeadm token create --print-join-command --certificate-key <key>
4. Add --control-plane --certificate-key <key> to join command
5. Run join command on worker
6. Copy kubeconfig
7. kubectl uncordon <new-master>
```

### **Verify HA Cluster:**
```bash
# Should show 3+ masters
kubectl get nodes -l node-role.kubernetes.io/control-plane=

# All etcd pods healthy
kubectl get pods -n kube-system -l component=etcd

# All masters schedulable
kubectl describe nodes | grep -i taint | grep -v "NoSchedule"
```

**Remember:** After upgrading worker to master, your cluster becomes **High Availability (HA)**. You'll need to:
1. Configure load balancer for API servers
2. Update kubeconfig to use load balancer IP
3. Consider etcd backup strategy
