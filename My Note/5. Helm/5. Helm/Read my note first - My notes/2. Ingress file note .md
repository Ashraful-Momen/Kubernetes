Below is **your Ingress YAML with line-by-line comments** explaining exactly what's happening at every line. This will help you fully understand Helm templating + Kubernetes behavior.

---

```yaml
apiVersion: networking.k8s.io/v1          # Defines the Kubernetes API group + version for the Ingress resource
kind: Ingress                              # Indicates this manifest creates an Ingress object
metadata:
  name: {{ include "django-app.name" . }}-ingress   # The name of this ingress, dynamically built from Helm helper
  labels:
    app: {{ include "django-app.name" . }}          # Adds a label "app=" for grouping and selection
spec:
  rules:                                   # List of routing rules for incoming HTTP requests
    - host: "{{ include "django-app.name" . }}.example.com"  # Hostname for ingress (you can point DNS here)
      http:                                # Specifies this rule is for HTTP traffic
        paths:                             # Path-based routing rules
          - path: /                        # Catch-all root path (example: http://hostname/)
            pathType: Prefix               # Prefix means `/anything...` matches
            backend:                       # Defines where the traffic should be routed
              service:                     # We're forwarding traffic to a Kubernetes service
                name: {{ include "django-app.name" . }}-service  # The K8s service name (must exist)
                port:
                  number: {{ .Values.service.port }}   # The service port comes from values.yaml (user-configured)
```

# EXPANDED EXPLANATION

### 🟦 `apiVersion` & `kind`

* Defines the type of Kubernetes resource.
* `Ingress` is used to expose services via HTTP(S) externally.

---

### 🟩 `metadata.name`

```yaml
name: {{ include "django-app.name" . }}-ingress
```

* Calls `_helpers.tpl`
* Gets chart name from `.Chart.Name`
* Example generated output:

```
my-application-ingress
```

---

### 🟨 `spec.rules.host`

```yaml
host: "{{ include "django-app.name" . }}.example.com"
```

* This defines the actual domain that routes to your application.
* If chart name = `my-application`, then result:

```
my-application.example.com
```

You would configure DNS so that this hostname points to your cluster's Ingress controller.

---

### 🟥 `paths`

```yaml
path: /
pathType: Prefix
```

meaning:

* Any request that starts with `/`

  * `/`
  * `/login`
  * `/hello/world`

will be routed to the backend.

---

### 🟧 `backend.service.name`

```yaml
name: {{ include "django-app.name" . }}-service
```

* This directs traffic to your Kubernetes service created in `service.yaml`

Example final output:

```
my-application-service
```

Ingress → Service → Pod

---

### 🟦 `backend.service.port.number`

```yaml
number: {{ .Values.service.port }}
```

* Reads from `values.yaml`:

```yaml
service:
  port: 80
```

* So final output:

```
port: 80
```

That means:

* Ingress forwards user traffic to service at port 80
* The service forwards it to pods at `targetPort: 8000` (defined earlier in service.yaml)
* Pods actually run the app on port 8000

    app: my-application

  rules:
    - host: "my-application.example.com"

                  number: 80
