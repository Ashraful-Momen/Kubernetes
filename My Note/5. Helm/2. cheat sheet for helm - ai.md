# Helm : build pkg for the helm. helm is the package manager for k8s.
-------

Overview:
- A Helm chart packages K8s manifests and templates so you can install/upgrade an application.
- Minimal chart requires: Chart.yaml, values.yaml, templates/ directory.
- Use `helm lint`, `helm template`, `helm package`, and `helm install/upgrade` to validate and deploy.

Chart basic files:
------------------
Chart directory structure (example):
my-chart/
  Chart.yaml
  values.yaml
  templates/
    deployment.yaml
    service.yaml
    ingress.yaml        # optional
    _helpers.tpl
    NOTES.txt           # optional post-install notes
  charts/               # dependencies (optional)
  README.md             # optional

1. chart.yaml:
-------------
apiVersion: v2
name: my-application         # Chart name
description: A Helm chart for deploying My Application
type: application
version: 1.0.0               # Chart version
appVersion: "1.0.0"          # Application version
maintainers:
  - name: Jane Doe
    email: 6Dm0k@example.com

2. values.yaml:
---------------

image:
  repository: myrepo/my-image
  tag: "latest"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: false
  host: example.com
  path: /

resources: {}
nodeSelector: {}
tolerations: []
affinity: {}

# Add more chart-specific values as needed

3. templates/_helpers.tpl:
--------------------------
{{- /*
Common template helpers for the chart.
*/ -}}

{{- define "my-application.fullname" -}}
{{- printf "%s-%s" .Release.Name .Chart.Name | trunc 63 | trimSuffix "-" -}}
{{- end -}}

{{- define "my-application.chart" -}}
{{ .Chart.Name }}-{{ .Chart.Version }}
{{- end -}}

4. templates/deployment.yaml:
-----------------------------
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "my-application.fullname" . }}
  labels:
    app: {{ .Chart.Name }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ .Chart.Name }}
  template:
    metadata:
      labels:
        app: {{ .Chart.Name }}
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - containerPort: 80
          resources:
{{ toYaml .Values.resources | indent 12 }}

Notes:
- Use `toYaml` and `indent` for nested values to ensure correct YAML indentation.
- Replace containerPort with your app port.

5. templates/service.yaml:
--------------------------

Common Helm commands:
---------------------
# Validate chart templates render (shows Kubernetes YAML)
helm template ./my-chart

# Lint chart for best-practices
helm lint ./my-chart

# Package chart into a tgz
helm package ./my-chart
# -> creates my-application-1.0.0.tgz

# Install (first time)
helm install my-release ./my-chart
# or install from packaged tgz
helm install my-release my-application-1.0.0.tgz

# Upgrade (or install if not present)
helm upgrade --install my-release ./my-chart

# Uninstall
helm uninstall my-release

# Show release history
helm history my-release

# Get values currently used by a release
helm get values my-release
helm get all my-release

# If you run a local chart repository (simple method):
# 1. Move tgz into a directory (e.g., ~/chartrepo)
# 2. Create index:
helm repo index ./ --url http://your-host/path/to/charts
# 3. Serve the directory over HTTP (e.g., nginx, python -m http.server)
# 4. Add repo:
helm repo add local-charts http://your-host/path/to/charts
helm repo update
helm install my-release local-charts/my-application

Tips & best practices:
---------------------
- Keep values.yaml small and put environment-specific overrides into separate files (e.g., prod-values.yaml).
- Use `helm lint` before packaging or installing.
- Use `helm template` to preview rendered K8s manifests.
- Use semantic versioning in Chart.yaml `version`.
- Keep templates idempotent and avoid hard-coding cluster-specific values.
- For chart repositories at scale, consider ChartMuseum or an object-storage backed repo.
